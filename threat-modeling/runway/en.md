# Threat Modeling Runway

1. **Architecture-first** — model the system before writing code.
2. **Version control** — keep threat models in the same repo as the code.
3. **Iterative** — update the model when architecture changes.
4. **Review in sprint** — discuss top threats during sprint planning.
5. **Test-driven** — turn identified threats into test cases for DAST/red team.

Reference: [OWASP Threat Modeling Project](https://owasp.org/www-project-threat-model/)
